# enricotagliavini.github.io

GitHub Pages site hosting self-produced RPMs as a DNF repository:

**https://enricotagliavini.github.io/repositories/ai-custom-infra/** (Fedora 44)

## How it works

GitHub Pages serves the site that the Actions pipeline publishes (Pages
source: "GitHub Actions"). The DNF repository is **not** committed here:
RPMs exceed GitHub's 100 MB per-file limit, so each release ships the whole
repository as a single `tar` + zstd **release asset**. The pipeline downloads
the asset, extracts it under `repositories/` (the three repos sit at the
archive root), and publishes `web/` + the extracted repos as the site.

Each release is organized like the main Fedora mirrors: the RPMs are split
into three repos under a per-version tree
(`<repo>/$releasever/$basearch`, e.g. `ai-custom-infra/44/x86_64/`), and only
`x86_64` is published:

- **ai-custom-infra** — binary RPMs
- **ai-custom-infra-source** — source RPMs (`.src.rpm`)
- **ai-custom-infra-debuginfo** — debuginfo / debugsource RPMs

repodata is regenerated for each repo at publish time, so new RPMs are always
visible to `dnf`.

```
local DNF repo (e.g. f44/)
   │ scripts/release.sh  → gh release ai-custom-infra-<ver> (asset attached; the local tarball is auto-removed)
   ▼
.github/workflows/deploy.yml  →  GitHub Pages (actions/deploy-pages)
```

## Updating the repository

From a machine with `gh` authenticated and the DNF repo directory ready
(RPMs in place):

```sh
./scripts/release.sh path/to/repo 1.1.0   # stages a copy, regenerates repodata, creates release ai-custom-infra-1.1.0, removes the local tarball
```

Creating the release triggers the pipeline automatically; the site is live a few
minutes later. To publish a new version, always use a new version string
(existing tags are rejected). The local tarball is removed automatically by
`release.sh` — on success or failure — so nothing is left behind.

Requirements: `gh`, `zstd`, `createrepo_c`, `git`.

## Installing on a client

Download the combined repo file from the [repositories landing
page](https://enricotagliavini.github.io/repositories/index.html) (also served
at `repositories/ai-custom-infra/ai-custom-infra.repo`). It lists all three
repos — binaries enabled, source and debuginfo disabled:

```ini
[ai-custom-infra]
name=AI Custom Infra
baseurl=https://enricotagliavini.github.io/repositories/ai-custom-infra/
enabled=1
gpgcheck=0

[ai-custom-infra-source]
name=AI Custom Infra - Source
baseurl=https://enricotagliavini.github.io/repositories/ai-custom-infra-source/
enabled=0
gpgcheck=0

[ai-custom-infra-debuginfo]
name=AI Custom Infra - Debuginfo
baseurl=https://enricotagliavini.github.io/repositories/ai-custom-infra-debuginfo/
enabled=0
gpgcheck=0
```

Save as `/etc/yum.repos.d/ai-custom-infra.repo`, then `sudo dnf makecache`.
Flip a repo's `enabled` to `1` when you need its packages.

## Layout

| Path | Purpose |
|---|---|
| `web/` | Static site content, copied verbatim to the site root (includes the repos landing page) |
| `scripts/release.sh` | Package + publish in one step (run locally, not in CI) |
| `scripts/build-site.py` | Stdlib-Python helper the workflow runs in its Build step to emit the per-repo package listings and the combined `.repo` file |
| `.github/workflows/deploy.yml` | Deploys `web/` + latest release asset to the Pages site (source: "GitHub Actions", via `actions/deploy-pages`) |
| `dist/` | Local-only (gitignored): DNF repo input and tarball output |

## Notes

- The deployed site is fully generated by the workflow — do not try to edit it
  directly; the next deploy replaces it.
- The URL paths `/repositories/ai-custom-infra/`,
  `/repositories/ai-custom-infra-source/` and
  `/repositories/ai-custom-infra-debuginfo/` are stable across releases; the
  version lives only inside the tree (`$releasever/$basearch`), so client
  `.repo` files never need updating.
- Each release is tagged at a **fresh marker commit** — a commit with identical
  site content but a unique SHA. GitHub Pages caches a deployment per commit SHA
  and would otherwise skip re-deploying one it already served, so this forces a
  rebuild every release.
- Packages are unsigned (hence `gpgcheck=0`). If GPG signing is added later,
  update the snippet above and the workflow's `web/` copy.
- See `AGENTS.md` for the invariants an agent (or a tired future you) must not break.
